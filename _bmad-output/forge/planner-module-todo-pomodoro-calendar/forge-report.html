Planner Module — Todo · Pomodoro · Calendar · Music

Forge session · Training Sanctum, module 2 · 16 Nov 2026 · for Luric

12 branches examined, 11 locked, 1 direction kept open with a verification task.

Outcome

The idea survived. It is now a four-epic module with every mechanism pinned down: tasks are free-form, the pomodoro plan is a binding budget with a bounded overrun, the calendar is a time grid that reports reality once a session starts, the timer is server-truth, XP is passive, and music streams from Jamendo. Hand-off: forged-idea.md → /bmad-correct-course.

Locked decisions

  • Q1Task is free-form. No link to Class/Folder, no auto-estimate from due cards.
  • Q2Plan is binding; estimate is a budget. 90 min → 25/25/25/15, last block is the remainder. Timer stops, asks "done?".
  • Q3Overrun bounded. "+1 session" at most twice per task (≤ +50 min), then only "not done". Overrun logged, estimate untouched.
  • Q4Calendar is a time grid. Tasks have an optional start time; pomodoro occupies a block; conflicts visible.
  • Q5Time semantics. Start time optional (unscheduled area). Block = plan incl. breaks (90 → 105 min). Late start moves the block to the actual start.
  • Q6Collisions: allow and draw. No auto-push, no blocking.
  • Q7Rollover: manual. Overdue badge + one "move all to today" action. Estimate and logged actual survive the move; replanning uses the remainder.
  • Q8Timer truth: server. PomodoroSession.startedAt on Start; one running session per user, enforced in DB.
  • Q9XP: passive. Session = X XP, task done = Y XP. No quests, no penalties.
  • Q10–11Music: full player on Jamendo. Per-category music, remembered, fade per session, CC attribution. MusicSource interface for later sources.
  • Q12Build order: Epic 8 Tasks → 9 Pomodoro → 10 Calendar → 11 Music.

Rejected, and why

  • Task linked to flashcard content — gold-plating; most tasks live outside the app's content.
  • Descriptive progress bar instead of a plan — the user wants the budget to cut, not to measure.
  • Unlimited "+1 session" — a budget you can exceed with one click is not a budget.
  • Auto-rollover or ask-on-open — contradicts the "tool I control" stance taken in every other branch.
  • Chain-push or block on collision — pushes hide changes; blocking stops the user from pressing Start.
  • Client-only or heartbeat timer — reload and device switches lose the session; heartbeat is the worst of both.
  • Pomodoro quests with penalties — exploitable via "+1" and fake tasks; the XP mechanic itself is still unproven.
  • Bundled files · YouTube embed · Spotify · uploads — user wants an API; iframe lacks volume control and has ads; Spotify needs Premium + OAuth; uploads need storage the app lacks.

Weak points that survived scrutiny

  • No use scene for the calendar. The time-grid choice was made without describing the "Sunday night" moment Sally asked for. It is the most expensive branch and the least justified.
  • Jamendo unverified. Terms page is dated 2013; lofi catalog quality unchecked. Must be verified before Epic 11.
  • Planned time is lost on start. Moving the block to the actual start discards the plan; only estimate-vs-actual minutes survive. Accepted for v1.
  • Assumed, not confirmed: task belongs to its start-time day across midnight; expired-on-reconnect sessions count as complete; "+1" sessions earn XP.
  • Easy agreement. Seven of twelve answers matched the facilitator's hypothesis verbatim. The user did diverge on Q4, Q5c, Q9, Q10, Q11.
