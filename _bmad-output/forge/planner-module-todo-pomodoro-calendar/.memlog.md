- (decision) Task = free-form item (option A). No link to Class/Folder; no auto-estimate from due cards. Module shares only user, XP and Pastel Frame with flashcards.
- (decision) Pomodoro plan is binding (option P): estimate is a budget. 90 min -> exactly 4 focus sessions 25/25/25/15 with breaks between; last session is the remainder, not rounded up. After the final session the timer stops and the app asks 'done?'.
- (lock) Not-done after final session: '+1 session' (one more focus block) allowed at most 2 times (<= +50 min over estimate). After that only 'mark not done' remains; to continue, edit the estimate and restart. Estimate stays as entered; overrun is logged so the user can recalibrate later.
- (decision) Calendar = time-grid (option 3): tasks have a start time, pomodoro occupies a time block, conflicts visible. This overrides the earlier date-only assumption. User did not describe the Sunday-night scene when asked.
- (lock) 5a start time optional; calendar has an 'unscheduled' area for timeless tasks. 5b calendar block length = full plan incl. breaks (90 min estimate -> 105 min block), so conflicts are real. 5c when pomodoro starts late, the block moves to the actual start time (plan is overwritten by reality; no two-layer calendar).
- (assumption) Consequence of 5c: planned start time is lost once started; only estimate-vs-actual minutes survive. Accepted for v1.
- (lock) Collision policy C1: overlapping blocks are allowed and drawn as a conflict; no auto-push, no blocking. User rearranges manually.
- (assumption) A task belongs to the local day of its start time even if its block ends after midnight; Day Settlement (5.7) does not touch tasks. Proposed, not explicitly confirmed.
- (lock) Rollover R1: unfinished tasks stay on their day as overdue. Todo page shows an 'N overdue' badge and a single 'move all to today' action; moving is manual. Estimate keeps its original value; already-logged actual minutes stay on the task.
- (assumption) Derived: when a task with prior actual minutes is started again, the plan is built from remaining = max(estimate - actual, 0); the 2x '+1 session' cap counts across the task's lifetime, not per day. If remaining = 0 only the buffer sessions are available.
- (lock) Timer truth T2: server-truth. Start writes PomodoroSession{startedAt, plannedMinutes, endedAt null}; client renders now - startedAt. At most one running session per user (DB constraint).
- (assumption) Sleep/offline case: a session found already expired on reconnect counts as completed (actual = plannedMinutes). Proposed, not explicitly confirmed.
- (lock) XP E1: passive XP only. Completed focus session = X XP, task marked done = Y XP, via new XpEventReason values. No quest, no settlement, no penalty for tasks/pomodoro. Values X,Y to be set in PRD.
- (assumption) Overrun '+1' sessions and sessions auto-completed on reconnect also earn session XP (keep the rule simple). Proposed, not confirmed.
- (direction) Music M2 chosen: meaningful player (music per category/task, remembered choice, fade in/out per session). Not locked until the music source is decided.
- (note) User asked for a free music API instead of bundled files. Researched: Jamendo (CC catalog, client_id, 35k req/month non-commercial, full-track stream URLs), Audius (free key, 500k req/month, full tracks), Radio Browser (keyless internet-radio stream directory), Free To Use (keyless royalty-free catalog).
- (lock) Music M2 on Jamendo (single source for v1): CC catalog via free client_id, tags lofi/chillout, full-track stream URL played in <audio> so fade in/out per session works. Music assignable per category (and overridable per task), choice remembered, attribution shown per track. MusicSource kept as a small interface so Audius/Radio Browser can be added later. Rejected: bundled files (user wants an API), YouTube embed (no volume control, ads), Spotify (Premium + OAuth), uploads (no file storage in app).

- (lock) Build order: Epic 8 Task & Category -> Epic 9 Pomodoro -> Epic 10 Calendar -> Epic 11 Music. Calendar before music.
