- (decision) Aesthetic pivot from PRD \u00a77 (Linear/Raycast dark-minimalist): new direction blends two references. PRD \u00a77 and \u00a72.2 will be updated to reflect this.
- (decision) spy-family.net (https://spy-family.net/) contributes COLOR PALETTE + EDITORIAL GRID LAYOUT only: sage/olive green canvas, deep red single accent, charcoal navy sidebar, white content cards, bold black sans-serif headers with small red square bullets, dense poster/cover-art grids. Applies to folder/card-browsing surfaces, not to review session itself.
- (decision) Quizlet contributes APP STRUCTURE only (not visual gamification): library/folder view = left icon sidebar + pill buttons + rows grouped under date headers + overflow menus + persistent top search; flashcard/study view = large rounded card surface, centered text, prev/next arrow nav, X/Y progress counter, shuffle/settings/fullscreen icon row, term-list rows (term+definition+icon actions).
- (decision) Explicitly excluded from Quizlet reference: Match/Blocks/Charms games, Study with Friends/Play live games, social Test mode, promo/upsell banners, AI chat bubble (Ask Quizlet) -- confirmed by user, consistent with PRD non-goals (no gamification/social).
- (decision) Review card reveal behavior: same card bounds before/after reveal, content swaps in place (prompt -> answer); grade buttons (Again/Hard/Good/Easy) appear below the card only after reveal, not inside it.
- (decision) Dark/light mode palette split: DARK mode = dark navy/charcoal base (Quizlet-like), red accent pop, sage green barely present. LIGHT mode = sage/olive green canvas + white content cards + red accent + charcoal text, close to spy-family.net as-is. Dark remains default per PRD \u00a77.
- (decision) Typography: system font stack throughout (-apple-system/Segoe UI/Roboto fallback chain), no custom webfont. Matches Linear/Raycast/Quizlet-app restraint.
- (decision) Empty due-queue state (landing screen when nothing due): shows current/longest streak summary (FR-15 subset), a congratulatory note, and a quick-add shortcut to capture a new card (realizes UJ-1 entry point) -- not a bare minimal message, not a fallthrough to folder view.
- (decision) Shape language: soft/generous corner radius throughout (cards, buttons, inputs) -- Quizlet-like friendliness, not sharp/editorial.
- (decision) Import UX (FR-6/FR-7): single unified Import screen with a Paste/Upload-file tab switcher; both tabs feed the same column-mapping + error-review step before commit.
- (decision) IA: primary sidebar nav = Review, Folders, Import, Stats, Settings (five flat sections, Quizlet-like icon sidebar).
- (decision) FR-15 stats visualization: bar chart of Scheduling Records grouped by current interval-length bucket (e.g. 1d/6d/2w/1mo/3mo+), per Recall Direction, as the primary SM-2 retention-curve view.
- (event) design-dna profile extracted via measured color analysis of the 3 reference screenshots (spy-family.net, Quizlet library view, Quizlet flashcard view), synthesized into one dual-theme profile at .working/design-dna-profile.json.
- (change) Review card reveal interaction refined: clicking the card performs a Quizlet-style 3D flip animation (card rotates to reveal the answer on its back face), not just a content swap. Card bounds still stay fixed (no resize) per the earlier 'same box' decision -- this only adds the flip motion to that same-box swap.
- (decision) Folder-delete confirmation (FR-5): centered modal, two explicit choices as buttons -- 'Move to Unsorted' (default/primary) and 'Delete cards too' (secondary/outline, danger-accent styled) -- no checkbox, user picks one action directly.
- (decision) Import result UI (FR-6/FR-7): after commit, a single results screen groups outcomes into 3 sections -- Created (N), Duplicates skipped (N), Errors (N, each with line number + reason) -- shown together, not a toast-only summary.
- (decision) Key Flows protagonist: Luric (the real builder/user, QA/Test Automation Engineer) narrated by real name throughout EXPERIENCE.md's Key Flows, not a generic persona -- single-user product per PRD.
- (decision) Mobile review input: tap-to-flip the card (touch equivalent of click), plus swipe gestures (left/right/up/down mapped to the 4 grades) as an added interaction layer for touch, alongside tap-targets on the grade buttons themselves -- not swipe-only.
- (decision) Restore-from-backup (FR-14) confirmation: simple warning modal stating the consequence ('This will replace all current data') with Confirm/Cancel buttons -- no type-to-confirm text input required.
- (decision) Settings screen scope: minimal, PRD-only -- daily new-card limit (FR-10), theme toggle (dark/light, FR \u00a77), export backup (FR-13), restore from backup (FR-14), logout (FR-1). No additional personalization options beyond these.
- (decision) Accessibility floor: WCAG AA contrast ratios required in BOTH themes (flagging sage-green light mode as the one needing explicit verification against white cards/charcoal text), plus clearly visible focus-ring/focus-visible states for full keyboard navigation. Deep ARIA/screen-reader optimization explicitly out of scope -- single-user product (the builder), not a general-accessibility requirement.
