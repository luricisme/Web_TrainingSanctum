- (direction) Coaching path chosen; spine-only deliverable (no separate human-facing write-up) since user is sole builder/dev.
- (decision) AD-paradigm: Next.js 16 (App Router) full-stack monolith. SM-2 engine lifted into a pure, framework-free TS package (packages/domain) with zero HTTP/React/DB imports, unit-tested in isolation. Binds: all layering. Prevents: domain logic leaking into API handlers or UI components, or becoming untestable without mocking a framework.
- (decision) AD-orm: Prisma ORM against Postgres (chosen over Drizzle) for guided migrations/DX, since user's QA/test-automation background favors spending effort on domain logic and test coverage over hand-written SQL/migrations.
- (decision) AD-hosting: Deployment target is Vercel (Next.js host) + Neon Postgres (free tier, serverless branching). No existing provider constraints.
- (version) Next.js 16.x (App Router, Turbopack default, Node 20+) confirmed current stable line as of Nov 2026 via web search.
- (decision) AD-auth: Auth.js (NextAuth v5), Credentials provider + Prisma adapter, database-backed sessions (not JWT), 30-day sliding expiry. Binds: FR-1/FR-2. Prevents: ad-hoc session/password handling, un-revocable JWT sessions, and friction-driven daily-habit abandonment from short expiry.
- (decision) AD-api-shape: Route Handlers (app/api/.../route.ts) as the sole API boundary, not Server Actions. Binds: all client-server calls. Prevents: integration tests exercising RSC internals instead of a real HTTP contract; keeps API/integration suite distinct from unit and E2E per PRD NFR.
- (decision) AD-grade-transaction: Grading a Scheduling Record is the single write path for SM-2 state (interval/repetitions/ease_factor/next_review_date): grade Route Handler loads current state, calls pure domain function, persists result in one DB transaction. No other path (UI, script, admin) writes these fields directly. Binds: FR-8 state mutation. Prevents: divergent/unsynced scheduling writes; enforces PRD \u00a75 non-goal (no manual scheduling-state edits) architecturally.
- (decision) AD-client-data: TanStack Query with optimistic updates drives the review loop. Grade action advances UI immediately, POSTs in background, reconciles/rolls back on failure. Binds: FR-9 sub-100ms perceived transition. Prevents: review UI blocking on round-trip latency, which would violate the NFR under real network conditions.
- (decision) AD-import-domain: Import parsing and duplicate-detection (FR-6/FR-7) are pure functions in packages/domain (parseImportBlock, detectDuplicates), called identically by paste and CSV Route Handlers. Binds: FR-6, FR-7. Prevents: paste and CSV import paths diverging on duplicate/validation rules.
- (decision) AD-validation: Zod is the single input-validation layer at every Route Handler boundary (body/query), before anything reaches domain or Prisma. Binds: all API endpoints. Prevents: malformed/edge-case input reaching domain logic as if valid.
- (decision) AD-testing: Vitest for domain/unit tests; Playwright for both E2E and API/integration tests (request fixture covers Route Handlers); GitHub Actions CI. Binds: PRD \u00a76 testability NFR. Prevents: a second, divergent test-runner setup for API vs E2E.
- (decision) AD-perf-budget: Due-queue/app-load budget = 200ms (distinct from FR-9's in-session 100ms transition standard). Resolves PRD \u00a710 Open Question 3.
