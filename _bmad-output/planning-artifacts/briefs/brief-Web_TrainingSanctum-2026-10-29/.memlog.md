- (decision) Solo personal tool for own language-learning workflow, not a multi-user product; no public browsing/sharing in scope
- (decision) V1 core features: create/edit sets (term+definition+example sentence+context), folders/organization, reversible flip-card study with SM-2 spaced repetition, CSV/paste import, accounts+progress+streaks
- (decision) Out of scope v1: Quizlet Test mode, Match game, public set discovery/sharing, mobile native app, audio/pronunciation
- (decision) Reversible cards (term->def and def->term) are a must-have; special character support needed for advanced English vocab/idioms/expressions
- (decision) Spaced repetition: classic SM-2/Anki-style algorithm from v1, chosen deliberately for portfolio rigor over simpler heuristics
- (decision) Tech stack open/TBD, leaning modern TypeScript/React/Next.js; final decision deferred to architecture phase
- (decision) Training Sanctum long-term vision: unified personal productivity+learning hub; flashcards is module 1, future modules include Pomodoro timer w/ background music and a To-Do/task manager
- (decision) Stakes: passion project + portfolio piece, craft over speed; working mode chosen: coaching path
- (decision) Problem/why: gap between Quizlet (paywalled SR, cluttered social UI) and Anki (unmatched algorithm, clunky UI, high-friction custom templates for extra fields). Want Anki's rigor + clean data model with Quizlet-grade modern minimal UI
- (decision) Native first-class language-card data model required out of the box: Term, Definition, Example Sentence, Collocation/Context, Part of Speech as structured fields, rendered cleanly in flip/review modes with no template hacking
- (decision) Dual driver, named honestly: (a) functional - distraction-free zero-paywall tool for contextual English acquisition with native SM-2; (b) career - user is a QA/Test Automation Engineer, building this to demonstrate production-grade, highly testable, end-to-end architectural craft as a portfolio piece
- (decision) Functional success criteria: card creation under 5s via quick paste/import; unbroken daily streak 60+ days with fast/keyboard-driven UX; observable SM-2 retention curve showing mature cards resurfacing at optimal intervals
- (decision) Portfolio success criteria: fully unit-tested SM-2 engine incl. edge cases (interval resets, ease factor boundaries, rating calc); clean Domain->API->UI separation with Playwright E2E + component tests + CI/CD; live public deployment with architecture docs, data models, and case study of engineering trade-offs
- (decision) Independent SM-2 schedules per card direction: single Card entity owns content fields, generates two CardDirection scheduling records each with own interval/repetitions/ease_factor/next_review_date (passive term->def vs active def->term recall differ cognitively)
- (decision) Phased delivery: Phase 1 (4-6wk) usable MVP - core CRUD, CSV import, dual-direction SM-2 engine, keyboard-driven review UI. Phase 2 (ongoing) - UI polish, Playwright E2E + CI/CD, architecture docs, portfolio case study. Posture: functionality before perfection, high craft before broad scope
- (decision) Risks: (1) scope creep from Sanctum vision - mitigated by hard v1 boundary to flashcards+SM-2 only; (2) data persistence/backup trust since daily-dependent - needs robust DB + export/backup strategy; (3) over-engineering vs shipping - balance portfolio-grade test coverage against actually shipping v1
